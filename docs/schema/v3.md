# v3 数据模型

本文档记录 PMWEB v3 数据根结构、任务字段、约束和 v2 到 v3 的迁移规则。校验实现位于 `tests/schema/validate.js`，测试位于 `tests/schema/validate.test.js`。

## 1. 版本

根对象必须包含 `pmweb_version`，类型为数字，值等于 `3`。缺失或为其他值都视为非法数据。

## 2. 根结构

| 字段 | 类型 | 必填 | 约束 |
|------|------|------|------|
| `pmweb_version` | number | 是 | 必须等于 3 |
| `tasks` | array | 是 | 元素为任务对象，见第 3 节 |
| `milestones` | array | 是 | 每项 `taskId` 必须指向存在的任务 |
| `links` | array | 是 | 依赖关系集合，v3 只校验容器类型 |
| `views` | array | 是 | 保存视图集合，v3 只校验容器类型 |
| `settings` | object | 是 | 非 null 且非数组 |

## 3. 任务字段

| 字段 | 类型 | 必填 | 约束 |
|------|------|------|------|
| `id` | string | 是 | 非空，同一数据集内唯一 |
| `parentId` | string \| null | 是 | null 表示根任务，非 null 时必须指向存在的任务 id |
| `name` | string | 是 | 非空 |
| `status` | string | 是 | 只能是 `inProgress`、`thirdParty`、`done` |
| `startDate` | string \| null | 是 | `YYYY-MM-DD` 或 null |
| `endDate` | string \| null | 是 | `YYYY-MM-DD` 或 null |
| `order` | number | 是 | 有限数字 |
| `progress` | number | 是 | 0 到 100，含边界 |
| `plannedEndDate` | string \| null | 是 | `YYYY-MM-DD` 或 null |
| `description` | string | 否 | 文本描述 |
| `assignee` | string | 否 | 负责人 |
| `color` | string | 否 | 任务颜色 |
| `ganttRow` | number \| null | 否 | 旧版行号，v3 不依赖 |

### 3.1 status 枚举

| 值 | 含义 |
|----|------|
| `inProgress` | 进行中 |
| `thirdParty` | 第三方 |
| `done` | 已完成 |

### 3.2 日期规则

日期使用严格的 `YYYY-MM-DD` 格式，并校验真实日历。`2026-02-30`、`2026-13-01`、`2026/01/12` 都不合法。null 表示未设置。

### 3.3 父子关系

`parentId` 为 null 表示根任务。非 null 时必须指向 `tasks` 中存在的任务 id，否则报告孤儿引用。

父子关系不能成环。任务直接或间接成为自己的祖先都算环，包括 `parentId` 指向自身。校验器会遍历父链并报告一次环错误。

## 4. 里程碑

`milestones` 是数组，每个元素是对象，必须包含 `taskId`。

| 字段 | 类型 | 必填 | 约束 |
|------|------|------|------|
| `taskId` | string | 是 | 非空，且必须指向存在的任务 id |
| `id` | string | 否 | 里程碑标识 |
| `name` | string | 否 | 里程碑名称 |
| `date` | string | 否 | 里程碑日期 |
| `status` | string | 否 | 里程碑状态 |

v3 校验器只约束 `taskId` 及引用完整性。

## 5. links 与 views

`links` 和 `views` 必须是数组。元素内部结构分别在依赖能力（P1-1）和保存视图能力（P1-4）中定义。v3 不校验元素字段。

## 6. settings

`settings` 必须是对象。设计文档约定的字段如下，后续可由应用补默认值。

| 字段 | 类型 | 说明 |
|------|------|------|
| `layoutVersion` | string | 工作台布局版本，默认 `workbench` |
| `gridWidth` | number | 表格面板宽度，默认 560 |
| `columns` | null \| array | 列配置，默认为 null |
| `statusFilter` | object | 三态筛选，键为 `inProgress`、`thirdParty`、`done` |
| `lastView` | string | 上次视图 |
| `lastGranularity` | string | 上次时间粒度 |

v3 校验器只要求 `settings` 是对象，不强制上述键存在。

## 7. 校验接口

```js
const { validateData } = require('./tests/schema/validate.js');

const result = validateData(data);
// result.valid 为 true 或 false
// result.errors 是数组，元素形如 { path, message }
```

字段路径使用点号和下标定位，根对象路径为 `$`。示例：

| path | message |
|------|---------|
| `pmweb_version` | `must be 3` |
| `tasks[0].status` | `must be one of inProgress, thirdParty, done` |
| `tasks[1].parentId` | `references unknown task id "ghost"` |
| `milestones[0].taskId` | `references unknown task id "missing-task"` |

`validateData` 不抛异常，任意输入都会返回结果对象。`valid` 等于 `errors` 为空。

## 8. v2 到 v3 迁移

迁移只增加字段，不删除或覆盖已有数据。

```js
if (version < 3) {
  data.tasks.forEach(function (task) {
    if (typeof task.progress !== 'number') {
      task.progress = task.status === 'done' ? 100 :
                       task.status === 'thirdParty' ? 30 : 50;
    }
    if (task.plannedEndDate === undefined) {
      task.plannedEndDate = task.endDate || null;
    }
  });
  data.links = data.links || [];
  data.views = data.views || [];
  data.pmweb_version = 3;
}
```

迁移规则：

- `progress` 缺失时按状态推导。`done` 补 100，`thirdParty` 补 30，其他补 50。
- `plannedEndDate` 缺失时取 `endDate`，`endDate` 也缺失则补 null。
- `links` 和 `views` 缺失时补空数组。
- 已有字段保持原值，不重新计算。
- `settings` 沿用原有内容。缺失时由应用补默认对象，保证导入后能通过校验。
- 迁移完成后 `pmweb_version` 置为 3。
- 旧版本应用读取 v3 数据会提示版本过新，升级前建议导出一次 JSON 备份。

## 9. 校验范围边界

v3 校验器覆盖根结构、任务必填字段、状态枚举、进度范围、日期格式、父引用、父子环、里程碑引用和集合类型。

以下内容留给后续阶段：

- `links` 与 `views` 的元素结构和引用完整性。
- `settings` 内部键的类型和取值范围。
- 里程碑除 `taskId` 外的字段。
- 业务层约束，例如里程碑日期必须落在任务日期范围内。
